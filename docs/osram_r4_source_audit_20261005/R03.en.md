## Actual objective, state, and solver

For column keys k_i, values v_i and queries q_t, define w_ti = beta_i product_{s=i+1}^t gamma_s, with positive static diagonal regularizer Lambda. The weighted cumulative objective is

`L_t(Phi) = 1/2 sum_{i<=t} w_ti ||v_i-Phi k_i||² + 1/2 Tr(Phi Lambda Phiᵀ)`.

The paper first presents the objective without input beta (Eq.4), then adds beta to the recurrent sufficient statistics (Eq.8); the beta-weighted objective above makes that extension explicit.

`G_t = gamma_t G_{t-1} + beta_t v_t k_tᵀ`
`H_t = gamma_t H_{t-1} + beta_t k_t k_tᵀ`
`Phi*_t = G_t (H_t+Lambda)^(-1)`
`o_t = G_t linsolve(H_t+Lambda,q_t)`.

G is value×key, H is key×key. Both carry all weighted history. Lambda is added at solve time, so forgetting decays data statistics but does not decay regularization. This supplies constant-sized history without retaining tokens.

MesaNet computes q* through CG, not an RLS recurrence of the inverse covariance or of Phi. Paper Algorithm 1 initializes with a diagonal-scaled query, updates residual/search direction, and exits using relative residual tolerance or maximum iterations. Rank-one and chunkwise matrix-vector products avoid materializing every per-token H. Earlier Mesa RLS has inverse-covariance recurrence and, with forgetting, problematic decaying regularization; MesaNet instead stores G/H and uses the stable positive-regularized linear system. CG gives a numerical approximation controlled by iterations/tolerance: “optimal” is the target objective, not a blanket claim of exact finite-step arithmetic.

Material source differences: production training chunk CG initializes x=0 (`chunk_cg_solver_fwd.py:112–120`), while production decoding uses diagonal initialization (`decoding_one_step.py:81`). Both execute a **fixed** maximum count, with 1e-5 stabilizers and no residual-based early exit. Therefore the paper's adaptive-compute property is not implemented by these pinned paths. With zero chunk CG iterations output is zero, whereas the paper discusses recovering GLA by taking q*=q at k=0; do not treat this FLA flag as that theoretical ablation.

Precision is version-sensitive: `chunk_h_fwd.py:152–156` now stores H in FP32, intermediate Gᵀ in BF16 by default, final states in FP32. [Upstream issue #1187](https://github.com/fla-org/flash-linear-attention/issues/1187) reports prior FP16-state NaNs and remaining reproduction concerns; that is an issue author's report, not our measured result. Current code visibly incorporates the precision change, so the old FP16 description must not be asserted for this pin.

## Comparison with existing OSRAM

The parent task calls the old update “_block_update”; current source names it `block_write` in `gcnet_missing_m3/osram.py:1323–1388`. With availability/beta-scaled Kbar/Vbar, it computes

`M_new = M + (Vbar-M Kbar)(KbarᵀKbar+rho I_3)^(-1)Kbarᵀ`.

For default write_step=1 and embedded beta, this is the proximal latest-block solution to

`1/2 ||Vbar-X Kbar||²_F + rho/2 ||X-M||²_F`.

That objective equivalence is an algebraic inference from inspected code, not a claim made by the source docstring. External-head beta / nonunit write_step additionally scale the correction.

- `1366–1375`: solve is the current three-slot Gram system; it is not historical key covariance. Only M is persisted, not cumulative H/G.
- `1447–1449`: decays the learned map M with static per-head alpha. Mesa decays sufficient statistics; because Lambda remains fixed, scaling both G/H is not generally equivalent to scaling Phi.
- `1451–1455,1488–1494,1502–1510`: current OSRAM reads decayed previous memory **before** writing the current utterance. Paper/Fla Mesa reads after incorporating the current token. Preserve this causal-history contract explicitly in an adaptation: read gamma-decayed G/H with fixed Lambda, then add observed current associations; label it historical-read Mesa adaptation.
- `1347–1367,1441–1446`: absent A/T/V columns are excluded. A Mesa block adaptation must sum availability-weighted outer products jointly for one utterance; applying decay between A,T,V would introduce arbitrary modality order.
- `1509–1510`: padding leaves state unchanged. Adaptation must preserve both G and H at padding, reset both at conversation boundaries, and avoid target labels in statistic updates.

Thus R03 is distinct **if it adds cumulative weighted G/H and the historical ridge objective**. Merely changing an existing solve or solver implementation does not establish a new mechanism. Direct torch.linalg.solve for short conversations would preserve the statistical objective but is a disclosed exact-solver adaptation, not a reproduction of MesaNet's CG/chunk throughput/adaptive test-compute claims.

## Acceptance evidence for a later implementation

Use the existing key/value/query projections and head sizes; add no dependency for this audit. Required checks: weighted full-prefix closed-form equality on a small sequence; read-before-write timing; masked-value perturbation invariance; padding no-op and conversation reset for both states; joint slot permutation invariance; finite forward/backward and nonzero expected parameter gradients; no-forget and zero-input cases; CG residual/error against exact solve if CG is chosen. Pin solver variant, dtype, Lambda, beta/gamma source, statistics dimensions and update timing in configuration. MOSI performance, GPU cost and training stability remain unmeasured.
