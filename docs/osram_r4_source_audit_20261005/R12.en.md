## Objective and implementation mapping

For m participating embeddings, define `d_ij=||y_i-y_j||_1`, `s_ij=-||z_i-z_j||_2/τ`, and `S_ij={k: k!=i, d_ik>=d_ij}`. Paper equations (1)–(3), pages 3–4, yield

`L_RNC = [1/(m(m-1))] Σ_i Σ_(j!=i) [-s_ij + log Σ_(k∈S_ij) exp(s_ik)]`.

The default two-view batch has m=2N; Appendix G.3 single-view/no-augmentation variants have m=N.

Equal-distance samples share denominator sets and compete within them; near-optimality encourages equal similarities rather than arbitrary strict order. A unique farthest target has a singleton denominator and contributes zero. All-pair means within the batch, not the entire training dataset on every step. Official loss has no padding/utterance mask, distributed all-gather, or minimum-batch guard. Its per-target matrix loop performs O(m³) work with O(m²) principal pairwise storage.

## Actual recipe

Paper page 3 and Appendix G.4 page 22 specify two stages: RNC encoder training followed by frozen-encoder regression. README L36–45 invokes `main_rnc.py`, then `main_linear.py --ckpt ...`.

1. `main_rnc.py:72–85/104–131` uses train split, shuffle, drop_last, and `TwoCropTransform`; `utils.py:6–11/14–48` creates independent crop/flip/color/grayscale image transformations. Encoder features directly feed RNC without projection head (`model.py:146–154`). Stage 1 has no regression loss.
2. AgeDB stage-1 defaults are 400 epochs, batch256, SGD lr0.5/weight_decay1e−4/momentum0.9, τ2 (`main_rnc.py:22–40`, `utils.py:76–100`). Stage 1 saves last without validation selection (`main_rnc.py:168–185`). Appendix F page 20 describes learning-rate/weight-decay grid searches and temperature selection; these image defaults are not established MOSI optima.
3. `main_linear.py:89–115/118–143/185–190` loads the encoder, uses eval/no_grad/detach, and optimizes only a linear regressor with L1. Defaults: 100 epochs, batch64, lr0.05, weight_decay0. The batch64 code default differs from the paper Appendix F's general batch256 description.
4. `main_linear.py:62–84/212–237` separates train/validation/test, selects the regressor using minimum validation L1, then evaluates that checkpoint on test once.

**Two views are not mathematically required.** The official default loader and loss API hardcode two views, but Appendix G.3 page 21 explicitly studies no augmentation and one-view augmentation, computing RNC over N embeddings, and explains that augmentation is unnecessary for RNC's validity. View count and the two-stage schedule are separate decisions.

## OSRAM transfer options and checks

The first proposed transfer is the paper-supported **single-view, no-added-augmentation, two-stage RNC** variant. Use genuine utterance embeddings from the existing observed mask and causal prefix, paired with original continuous MOSI labels. Filter padded utterances before pair construction; preserve conversation forward ordering and memory updates, comparing samples only at the loss. Stage 1 optimizes RNC; stage 2 freezes the entire representation path and trains the readout. This introduces label-distance ranking without assuming invariance to different missing masks or histories.

If the task requires the existing single-stage cfg84 budget, `MSE+λL_RNC` is possible but must be named an OSRAM single-stage RNC auxiliary objective, not an original-framework reproduction. It changes the stage structure, objective and gradients. Fix λ, τ and feature tap using validation and explicit configuration; do not tune using test-oracle feedback.

A default two-view transfer would need identical legal causal prefixes and observed masks, with justified label-preserving augmentations. Treating different histories, full versus missing modalities, or different missing masks as zero-distance views adds history/missingness invariance; document that assumption and its controls before adoption. It is not the default proposed transfer.

Labels enter training loss distance calculations only, never memory writes or inference inputs. Do not feed batch labels, future-utterance features or unavailable modalities to the encoder. No validation/test optimization or cross-split comparison pools. Cross-conversation loss supervision does not authorize changing causal input semantics.

Required checks: differentiable zero when fewer than two valid samples; exact `>=` tie handling; scalar label shape; complete padding exclusion; finite equivalent logsumexp implementation with extreme-distance gradients; permutation invariance; masked/future feature changes leave current representation unchanged; intended encoder/readout freeze/update behavior. A two-view batch with one valid underlying instance has no useful inter-instance ranking supervision.

R12 remains a candidate under the sole name Rank-N-Contrast. Its substantive distinction is anchor/target-dependent denominator sets determined by continuous label distances, supervising batch-wide pair rankings. Single-view usage has paper precedent; a joint one-stage MSE objective is a new transfer design. OSRAM implementation/performance evidence is absent and the source license remains unresolved.
