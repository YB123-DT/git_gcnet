## 修正筛选标准

1. 迁移完整机制：例如消息传递→状态更新→重新计算关系，或向量投票→竞争分配→一致性迭代。
2. 机制必须在当前输入上成立。Local 是一个向量，不能冒充词序列；head 不是图像 patch、物体或历史时刻。
3. PDF 方法与作者实际实现分别核对，记录不一致和代码缺口，不以论文名气代替适配判断。
4. 算法差异优先于参数量。公共投影和输出层的参数不应被用来证明核心机制足够丰富。
5. 只处理本次已经算出的 Local/Base/Gap；不增加 OSRAM 读写、第二次查询、时间缓存、补全、标签输入或额外损失。
6. 不把所有源方法裁成同一个单层残差小算子。可保留稳定初始化的残差接口，但不能因此删除源方法的关键迭代或状态流。
7. 迁移的独立性与论文创新性分开判断；借来的完整 Block 也不自动构成 OSRAM 的研究贡献。

## 已核实的真实输入结构

当前 `gcnet_missing_m3/osram.py`：

- `MODALITIES` 为 audio/text/visual。
- `_scan()` 的 Base/Gap 先产生 `[B,H,value_dim]`，再展平；cfg84 的 forward 512 确实来自 8 个 64 维 head。
- forward 与恒零 backward half 再拼成 1024；新机制可仅用真实 forward 部分，不改旧 Flat 输入。
- 五个名义槽位为 `[Local,Base,Gap-A,Gap-T,Gap-V]`，但每句至少一个模态可见，所以通常只有 2–4 个 active 槽。
- 若保留真实 head，则有一个 Local token，加 8 个 Base tokens，以及 0/8/16 个 active Gap tokens，即 9/17/25 个输入；无历史或 padding 另行跳过。
- 同一 head 下 Base 与 Gap 读取同一 head 的记忆值空间。不同 head 的通道并不天然对齐；投影和 head identity 必须明示。
- head 索引不具有空间邻接、时间间隔或已知情绪角色。

这是可能利用的真实结构，不是为使用某篇论文而把向量任意切块。

## 优先保留的结构方向

以下是**待设计的迁移判断**，不是源论文对 OSRAM 的结论，也不是已获提升的候选。

| 方向 | 必须保留的完整机制 | 适配判断与限制 |
|---|---|---|
| [RRN](https://arxiv.org/abs/1711.08028) | 有效证据对之间发消息→聚合→共享递归更新→再次交互；每轮重新注入原输入 | 最直接。五槽即可，不必制造物体语义；多轮不是读到更远历史。原逐步监督不沿用，必须记录此变化；作者代码未发现许可证，不能直接复制 |
| [EGT](https://arxiv.org/abs/2108.03348) | 节点状态与显式边状态共同更新；边影响下一层节点，节点信息更新边；保留多层反馈 | 结构性最强。需事先定义仅由真实角色/head 身份构成的图，不把边解释成可靠性或物理关系；单层后丢弃边状态不算完整迁移 |
| [Capsule routing](https://arxiv.org/abs/1710.09829) | 证据向量生成不同输出的 votes→竞争分配→向量聚合与 squash→一致性更新→再路由 | 条件保留。路由状态每句重置；无需图像网格，但不使用原 margin/reconstruction loss，也不把胶囊范数称为情绪概率 |
| [Slot Attention](https://arxiv.org/abs/2006.15055) | 输入竞争分配到多个临时槽→归一化聚合→GRU 与残差细化→反复更新 | 条件保留，更适合真实 head 集合。明确原代码在 eval 也随机初始化；需固定可复现方案。输出仅是潜在证据组，不是物体或补全模态 |
| [Perceiver IO](https://arxiv.org/abs/2107.14795) | 证据编码到临时 latent workspace→latent 内处理→Local 条件输出解码 | 次优备选。可不再访问 OSRAM；当前输入很少，没有大规模输入效率优势，必须说明为何需要该中间表示 |

RRN 和 EGT 的区别不是参数多少：前者主要更新证据节点，关系消息每轮重新计算；后者另外保存并迭代更新**本次读出内部的边表示**。这些状态在当前 utterance 结束即丢弃，不是第二个跨时刻 Memory。

## 为什么不把其他大模型直接塞进来

- Restormer/XCiT 的完整块包含真实空间交互；拿掉它们只剩通道注意力，保留则需要伪造网格。
- CrossViT 的双尺度不是 Local/Memory 两个名字能替代的。
- GMN 需要两组有意义的图；单个 Local 对一个证据集合不能保留完整双向图匹配。
- MAC/NSM 的词序列控制或语义场景图不能由当前五槽自然提供。
- 多数阅读理解匹配网络需要两段有序序列，不能把 256 个 Local 通道当作 256 个词。
- HGT、Set Transformer、Universal Transformer 暂列备选；仅抽出类型注意力或共享层堆叠不足以满足本轮要求。
- NPS 有完整的稀疏规则执行链，但代码来源与规则/实体适配尚有缺口，不能计作已核实候选。

逐篇证据、作者数组、原文位置、实际代码和限制见四个 JSON 文件及 `paper_bank.json`。没有核实到的代码明确留空。

## 下一步边界

重新选型应围绕**证据间的结构化处理**，而非把 scalar gate 变成大 gate。
优先把 RRN/EGT 的输入、每轮状态、mask 和输出写成确切计算图，再决定哪些完整机制进入新的单种子清单；其余条目继续按相同标准补齐，不能用二十篇已浏览论文冒充二十项合格实现。

本次没有给出新超参、训练命令或分数；也未把这些方法交给旧队列。
仅凭结构不能断言提升，更不能断言恢复了整个缺失模态的信息。
最终仍需与同协议 cfg84 Flat 比较；任何 Test-oracle 筛选必须明确标记内部诊断并报告全部运行。
