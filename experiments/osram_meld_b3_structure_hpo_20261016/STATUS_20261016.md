| Parameter | Current implementation | Possible later comparison | Current CLI support |

| B3 attention heads | 4 | 2 / 4 / 8, dividing internal width | Requires new B3-specific configuration |
| B3 FFN hidden width | 256 | 128 / 256 / 512 | Requires new B3-specific configuration |
| B3-local dropout | No dropout inside the B3 core | 0 / 0.1 / 0.2 | Requires implementation; global dropout0.5 is not this parameter |
| B3-specific learning rate | Inherits original task optimizer lr0.001 | 0.0001 / 0.0003 / 0.001 | Requires a B3-specific optimizer group; B6-only multiplier is not applicable |

The existing two exposed B3 settings remain bottleneck tokens and synchronous
rounds only. None of these later options was added to the active twenty-trial
study. If future structural tuning is authorized, internal width and FFN width
are direct capacity comparisons; they do not require changing CHM's eight memory
heads or the Flat1600 representation.

Implementation nuance: a role consumes the previous bottleneck in each round;
the first round starts from learned constant tokens. With only one round, the
newly aggregated source-dependent bottleneck does not feed back into role output.
Thus the rounds1 control also removes this cross-role feedback, rather than being
merely a smaller parameter count. This is recorded without changing the existing
mechanism or ongoing jobs.
