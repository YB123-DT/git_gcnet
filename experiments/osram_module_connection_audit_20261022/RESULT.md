# 模块连接方式与提分停滞：代码和既有实验联合审查

2026-10-22。OSRAM 审查起点：`feature/ecerc-features`，`b21f249747a813230b095d23218be011d70ba6d1`。

这是代码审查和已有结果整理。没有启动新模型训练、测试集推理或参数搜索，没有修改模型、Mask、已有实验或 checkpoint。另做了四步**合成输入 CPU 梯度检查**，临时模型随进程销毁，仅验证初始化的计算图，不是性能实验。

## 1. 最有依据的判断

**目前最值得停止重复的，是把不同论文的机制反复装进同一个“对已读出的证据作可选校正”的任务。** 多个机制在原论文里承担不同职责，移植后却常常变成：读取已经融合/压缩过的 Local、Base、Gap，输出小维度变换，再交给原大 Flat，全部依靠同一个情感损失学习。

这是一项能从代码确认的搜索空间特征，以及解释现有结果的工作假设；**还不能把它写成已经唯一定位的失败原因**。下面的反证同样重要：

- 别人的模型也大量使用残差，甚至保留绕过图消息的拼接路径。
- MISA、ConFEDE 也处理句级向量；句级压缩本身不能解释差异。
- Self-MM、MMIM 的特色模块不进入最终预测数值，但通过训练目标改变共享表示。因此“强制经过新模块”不是有效方法的必要条件。
- 你已经尝试过直接替换、冻结原主干、增加原始短窗历史等不同接法；不能把过去所有实验误说成同一种残差，也不能再承诺删除残差或换输入就会有效。

**目前可以排除的强说法**是“Memory 完全没有用”“所有新模块都没参与计算”“只因为残差压住了它”“只要参数更大就能涨”。仍未分开的，是剩余可利用信息的多少、模块归纳偏好是否合适，以及联合优化能否稳定提取这部分收益。

## 2. 你的模型实际怎样连接

### 2.1 原 Flat 本身已经是一条完整融合路径

当前标准维度为 Local256，Base/三个 Gap 各1024，其中因果有效前向512。实际输入是4352维：

`[L256, B1024, G_A1024, G_T1024, G_V1024]`

原 Adapter 是：

`LayerNorm(4352) → Linear(4352,1600) → GELU → Dropout → Linear(1600,1600)`

再与 `LocalSkip(256→1600)` 相加，经 LayerNorm 和任务头。Adapter 参数 **9,535,104**，约占原 MOSI 模型13,509,793参数的70.6%。这是模块参数统计；不能据此认为所有维度都同等有效，也不能仅凭参数大小证明它已经最优。

代码：[osram.py:1157](../../gcnet_missing_m3/osram.py#L1157)、[Adapter:1165](../../gcnet_missing_m3/osram.py#L1165)、[输入和接回:2150](../../gcnet_missing_m3/osram.py#L2150)、[任务头:2183](../../gcnet_missing_m3/model.py#L2183)。

所以多数后加算子需要提供的是**超出这条既有融合路径的增量价值**，不是第一次让 Local 和历史相遇。原 Flat 有非线性容量，不代表能高效学会所有关系；但“增加一次交互”本身不是缺口证据。

### 2.2 至少要区分这些接法

| 家族 | 实际连接 | 模块接收的对象 | 可以改变什么／没有新增什么 |
|---|---|---|---|
| MeaningfulReadoutResidual / 旧 SourceRelation | `LN(S(L)+A(X)+Δh)` | 已读出的证据；SourceRelation 另有来源分解 | 补充隐藏表示；原完整预测路径仍在 |
| 原 Nested / 多数 TokenAdapter | `LN(S(L)+A(X+ΔX))` | 同一时刻各角色的 Memory head 切片 | 重组读值；不是在历史话语节点之间重新检索 |
| Direct-input GAT/PNA/CWN/Perceiver/Nested | `LN(S(L)+A(X'))` | 还是读后证据，输出替代 Adapter 输入 | 取消外部原证据加法；原 Local Skip/Flat 仍保留，部分内部残差仍存在 |
| Source-Role direct | `B',G'=Σ_s γ_{r,s}R_{r,s}`，再接原 Flat | 联合写入的来源分解和轨迹 | 来源缩放；不是产生独立历史内容 |
| V3 residual | `B'=B+ΔB, G'=G+ΔG`，再接原 Flat | 来源×角色12槽及轨迹 | 有更多来源可辨信息，但最终仍为原读取空间的校正；仅缺失且有历史时启用 |
| 短窗历史 / B1一类 | 直接读原先的历史 latent，再加到 Flat 前 | 可访问保留的过去话语/模态 token | 确实增加原摘要之外的访问路径；已有有限实验也未保证收益 |

依据：[MeaningfulReadoutResidual](../../gcnet_missing_m3/meaningful_blocks.py#L34)、[TokenAdapter](../../gcnet_missing_m3/meaningful_input_new40.py#L18)、[输入包装](../../gcnet_missing_m3/meaningful_input.py#L74)、[Source-Role](../../gcnet_missing_m3/source_role.py#L88)、[V3接回](../../gcnet_missing_m3/osram.py#L1987)。

原 Nested 的33节点是 `Local + 4读取角色×8个head`，不是33句历史话语。图的邻居是读值角色/head，不能把它解释成重新寻找“过去哪句话有帮助”。[HeadTokenizer](../../gcnet_missing_m3/meaningful_blocks_common.py#L12)、[NestedGNN](../../gcnet_missing_m3/meaningful_new40_structure.py#L323)。

V3与普通读后变换也有实质区别：`JointSourceTracker` 保存了共享 Memory 求和之前的来源分量；这些分量通常不能只凭已求和 Base/Gap 唯一还原。不能称V3“完全没有额外信息”。但它仍没有保存每条历史话语身份，也没有修改原读取方向。[来源追踪](../../gcnet_missing_m3/tasr.py#L39)。

### 2.3 V3 的输出约束比内部网络名称更关键

V3先共享512→64投影，同源 Base–每个 Gap 配对，再同角色跨来源 Attention，最后每个角色用 Local Query 汇总三个来源成64维，再线性映射回512维。

因此，最终每个角色的校正量仍受64维中间表示约束，并且原读值直接保留。内部用了两层 Attention，不等于保留了12路独立输出，也不等于增加了历史时间上的检索。它可以学到有效变换，但接入职责必须按这个真实出口解释。[source_role_v3.py:28](../../gcnet_missing_m3/source_role_v3.py#L28)、[输出:126](../../gcnet_missing_m3/source_role_v3.py#L126)。

## 3. 其他论文代码：到底哪里不一样

核对了8个论文仓库，另将原GCNet作为继承关系参照。具体提交、代码行和实际损失见 [CODE_EVIDENCE.md](CODE_EVIDENCE.md)，文件哈希见 [SOURCE_MANIFEST.json](SOURCE_MANIFEST.json)。这里只比较代码事实，没有复现或比较这些论文的成绩。

| 方法 | 真正的数据流／训练连接 | 与大部分 OSRAM 读出校正的区别 |
|---|---|---|
| **MulT** | 三模态特征序列 → 跨模态Attention → 各目标序列的Memory Transformer → 拼接 → 残差MLP → 预测；只用最终任务损失 | 在序列汇总前建立跨模态联系；后续消费交互后的序列。Attention和最终MLP都有残差，不是“没有旁路” |
| **MISA** | 三个句级向量 → shared/private六个向量 → Transformer → 拼接 → 主预测；另有差异、相似性、重构目标 | 六个新表征就是预测输入；损失直接约束拆分。不是给既有完整融合结果追加一个无明确拆分监督的旁支 |
| **ConFEDE** | 预训练句级编码器 → 六个simi/dissimi投影 → 拼接 → 主预测；分支回归与对比学习约束这些投影 | 将重新组织的表征交给预测，并配套两阶段训练/采样。并非只移植一个拆分MLP |
| **DLF** | 序列shared/specific拆分 → specific语言引导跨模态交互 + shared融合 → 主预测；多出口任务和表示约束 | 后一模块使用前一模块区分出的表示；训练同时约束中间表示。自身也有多处残差 |
| **Self-MM** | 编码器输出三路句向量 → concat+MLP主预测；单模态heads经动态伪标签辅助训练共享编码器 | 特色分支通过梯度起作用，根本不加到主预测。只把几个head装进OSRAM前向，不等于复现训练机制 |
| **MMIM** | 三路句向量 → concat+MLP主预测；MI/CPC估计器约束单模态与融合表示 | 创新主要体现在明确的优化目标及交替训练；不是一个更复杂的最后融合层 |
| **ComP** | 模态内shared/private → 跨模态prompt注入 → 两段模态处理 → 模态heads与router联合预测 | prompt为此前模态内的流加入其他模态通道；分解、模态预测、联合预测有对应训练目标。原版还含全序列非因果运算 |
| **SDR-GNN** | 上下文节点 → RGCN→Hypergraph→signed消息传播 → 与原节点拼接 → 后续时序编码 → 任务/重构 | 模块改的是跨话语传播；存在局部旁路。当前官方提交还发现speaker支路未实际接入输出的tuple问题，不能拿代码表面层数当有效机制证据 |
| 原 **GCNet** | 已上下文化节点 → temporal/speaker图 → 各分支拼接原节点→时序编码 → 分类与缺失重构 | 图使用话语/说话人关系；重构头虽不直接进入默认预测，但对共享表示提供完整缺失特征监督 |

从这张表真正能学到的不是“改为concat”“不要残差”或“加辅助Loss”，而是三个问题必须一起回答：

1. **后一个模块收到什么尚未被前一个模块充分表达的信息或关系？** MulT的token对应、ComP的跨模态输入通道、原GCNet的话语/speaker关系，与把同一读值分成8块再连接不是同一个操作对象。
2. **中间表示怎样被下一阶段使用？** MISA/DLF预测头消费新表示；你的许多变体只是让原有融合器多一个可选修正。两种都可能有效，但实验假设不同。
3. **什么梯度约束这项职责？** MISA/Self-MM/MMIM有具体训练目标；MulT说明单任务损失也可以成立。没有理由照搬全部辅助损失，更不能把“定义了某个head”当成它参与了训练。

## 5. 本次发现并验证的初始化细节

原 `emotion_adapter[-1]` 自身零初始化；V3的四个decoder也零初始化。V3校正在原Adapter的**输入侧**，所以从头训练的第一次反向传播中，原Adapter最后一层为零，会把传向V3的任务梯度挡住。

记原Adapter为 `W₂ φ(W₁x)`、V3校正为 `Dφ_v3(·)`。在 `W₂=0,D=0` 时，V3 decoder的梯度也为零。原 `W₂` 先更新，下一步 `D` 才开始更新，再之后V3内部网络才得到梯度。这与在最终hidden上直接加零初始化残差的首步路径不同。

本次用**实际OSRAM/V3实现、标准维度、随机输入、CPU、四步临时Adam**验证：

| 第几次 backward | Flat最后层梯度范数 | V3 Base decoder | V3 PairMLP | V3来源Attention |
|---:|---:|---:|---:|---:|
| 1 | 7.639775 | 0 | 0 | 0 |
| 2 | 7.064045 | 0.284228 | 0 | 0 |
| 3 | 5.017679 | 0.313444 | 0.101972 | 0.014748 |
| 4 | 8.913265 | 0.634138 | 0.220265 | 0.032864 |

结论仅为：**有短暂的梯度启动延迟，不存在由这两个零初始化必然造成的永久断梯度。** 本检查不足以支持用这两三步延迟解释长期成绩，也没有排除初始化影响后续优化轨迹；原真实数据smoke已验证后续梯度连通。不能拿首步零梯度或很小的残差单独解释长期失败。

[检查代码](check_initial_gradients.py)、[完整输出](INITIAL_GRADIENTS.json)。为隔离拓扑，dropout和WD设为0；不是原训练曲线，也没有使用MOSI标签或checkpoint。

## 6. 现在应如何判断第二Block是否值得继续

我会先要求每个候选写清三个具体交接关系，而不是继续收集模块名称：

- **Block1交给Block2的对象**：是当前各模态latent、逐条历史、共享Memory、Query读值，还是来源分量？这些对象不能互相改名替代。
- **Block2交给预测器的对象**：是预测所依赖的新表征、对原证据的修正、额外条件信息，还是只在训练期产生梯度的目标？必须按真实计算图选择解释和消融。
- **相对已有最接近实验的区别**：新增了哪一种可访问关系、表示约束或训练责任？若只是同一输入/同一损失/同一出口下换一个融合算子，应按相近假设处理，不能当作全新问题。

对当前路线，证据支持降低“再加一个末端交互网络会稳定涨分”的预期。若继续保留小Flat+V3，现阶段最稳妥的成果是**大幅减参、平均分接近**，高缺失与多种子仍有代价，不能改写成已解决来源协作。若要新研究问题，应从一个尚未被现有实验覆盖的具体职责开始；本次审查不据此自动创建新模块或启动下一轮训练。

## 7. 核验与限制

- 读了实际模型前向和实际训练调用，不只看README、类名或声明的loss。
- 参考仓库核心文件为对应Git快照；GCNet工作区虽有本地配置变动，所引用五个核心文件与upstream版本一致。详见来源清单。
- 交付前重新核对66个来源/结果文件的SHA256、28个本地引用以及41个固定提交的源码链接；均与记录一致，引用行号存在。合成梯度检查的断言通过；未运行全仓测试，也未复现参考论文性能。
- 静态比较不构成跨论文效果归因。原代码的数据、可训练特征编码器、因果范围、loss、missing协议与OSRAM并不一致。
- 只审查有代表性的连接方式和指定证据；没有把上百个历史实验重新排序，也没有声称所有实验都是读出残差。
- 本次新增文件只有本目录的报告、来源记录、合成梯度检查及其结果。原模型、已运行任务、旧代码和权重均未改。
